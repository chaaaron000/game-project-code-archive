# 게임 프로젝트 코드 아카이브

게임 프로그래머 포트폴리오와 면접 준비를 위해 여러 프로젝트의 코드와 개발·검증 사례를 한곳에 모아 정리한 저장소입니다.

> 이 저장소에 파일이 포함되어 있다는 사실만으로 해당 파일 전체를 제가 작성했다는 뜻은 아닙니다. 팀 프로젝트 코드는 함께 보관하되, 각 프로젝트의 `README.md`에서 제가 직접 구현한 부분, 기존 코드에 수정·연동한 부분, 팀원이 구현한 부분을 구분해 설명합니다.

## 정리 기준

- **직접 구현** — 제가 설계하고 주도적으로 작성한 코드
- **수정·연동** — 기존 팀 코드에 기능을 추가하거나 구조를 변경한 부분
- **팀원 구현** — 다른 팀원이 주도적으로 작성한 코드로, 제 기여로 설명하지 않는 부분
- **확인 필요** — 현재 커밋 이력만으로 작성 범위를 확정하기 어려운 코드

## 코드 폴더 구조

원본 프로젝트는 개발 당시의 폴더 구조가 일관되지 않은 경우가 있어, 이 저장소에서는 **코드 내용은 수정하지 않고 경로만 기능과 책임 기준으로 다시 분류**했습니다. 따라서 여기의 폴더 경로는 원본 Unity 프로젝트의 실제 경로와 다를 수 있습니다.

프로젝트에 따라 필요한 폴더만 사용하며 대체로 다음 기준을 따릅니다.

- `Gameplay` — 실제 게임 규칙, 플레이어, 맵, 아이템, 스테이지 등
- `GameFlow` — 게임 시작·종료, 장면 전환, 전체 진행 관리
- `AI` — 몬스터와 상태 머신
- `Network` — 멀티플레이, 세션, 음성 채팅
- `Systems` — 블랙보드처럼 여러 기능에서 사용하는 독립 시스템
- `UI` — 화면과 사용자 입력 표시
- `Settings` — 게임 설정과 접근성
- `Audio` — 배경음과 효과음
- `Data` — 저장 데이터 등
- `Editor` — Unity 편집기 전용 도구
- `Common` — 공통 기반 코드와 보조 기능
- `Platform` — Steam 등 외부 플랫폼 연동
- `Debug` / `Legacy` — 테스트 코드나 분류 가치가 낮은 과거 코드

비주얼 노벨 프로젝트처럼 코드 공개보다 개발 흐름 자체가 중요한 사례는 별도 설명 문서만 보관합니다.

## 작성 범위 확인 방법

팀 프로젝트의 현재 파일만 보고 작성자를 추정하지 않습니다. 가능한 경우 원본 저장소의 커밋 작성자와 변경 내용을 확인해 각 프로젝트 문서에 근거를 남깁니다. 한 파일에 여러 사람이 수정한 코드가 섞여 있다면 파일 전체를 제 코드라고 표현하지 않고, 제가 추가하거나 변경한 기능의 범위만 설명합니다.

## 제3자 코드와 외부 자산

유료 에셋, 패키지 원본, 외부 개발 도구의 구현 코드, 튜토리얼에서 가져온 코드처럼 재배포하거나 개인 구현으로 제시하기 부적절한 소스는 가능한 한 제외합니다. 프로젝트 코드와 제3자 코드가 섞여 있을 가능성이 있는 경우에는 문서에서 별도로 표시합니다.

## 목적

이 저장소는 실행 가능한 Unity 프로젝트를 재현하기 위한 저장소가 아니라, 과거 프로젝트의 실제 코드와 제 기여 범위를 면접과 포트폴리오에서 확인하기 쉽게 보관하는 자료 저장소입니다.
